LeakBase · 개인정보·보안 유출 사고 아카이브 · 와이어프레임 8개 화면

4주차 서비스 구조 및 UX 설계 산출물. 색상과 이미지를 배제하고 정보의 우선순위, 행동의 위치, 화면별 데이터 항목을 검토하기 위한 설계 도면. 사고명·서비스명은 모두 가상 샘플이며 실제 기업과 무관함. 내 서비스 사고 연표와 조치 도장을 포함하며 화면 수는 8개임.
핵심 사용자 유출 뉴스를 보고 내가 쓰는 서비스가 해당되는지 확인하려는 일반 이용자(대학생 포함) 기준 화면 모바일 세로 375pt 화면 수 8개 · 5가지 화면 상태 포함

표기 규칙

영역 블록 버튼, 입력창, 배경이 있는 영역 본문 자리 (문구 미확정) 점선 영역 화면 상태 변형 점선 칩 개인화 경고 배지 (조건부 노출) 처리

이 도면에서 확인한 설계 판단

  • 화면 8개, 최대 3단계 — 온보딩 · 홈 · 사고 목록 · 사고 비교 · 사고 상세 · 내 서비스 관리 · 관심/최근 사고 · 체크리스트 모아보기. 추가 기능은 기존 화면 안에 배치해 화면 수와 하단 메뉴 구조(홈·내 서비스·관심)를 유지함
  • 연표는 내 서비스 관리 안에 배치 — "내 서비스를 등록하면 보이는 결과"라는 의미를 살리기 위해 별도 탭이나 화면으로 빼지 않음. 서비스를 지우면 연표에서도 빠짐
  • 연표·도장·경고 배지는 전부 계산값 — 새 저장 데이터 없음. 연표는 org · date , 도장은 checklist:{id} , 배지는 watchedCategories · leakedItems 로만 계산
  • 도장은 "처리함"만 표현 — 도장이 찍혀도 "안전함"을 뜻하지 않음. 판정 금지 원칙 유지
  • 사고 비교는 상세와 같은 필드 재사용 — 새 데이터 구조 없이 항목만 표 형태로 재배치
  • 보조 사용자는 필터 값으로 수용 — 정보보안 전공 대학생은 type · cause 필터로 수용
  • 상세에서 목록 복귀 시 조건 유지 — 깨지면 목록과 상세를 반복 이동하는 문제가 재발함
  • 5가지 화면 상태 유지 — 초기(홈) · 로딩 · 결과 없음 · 오류 · 저장 완료. 연표 비어 있음은 결과 없음의 변형, 도장 찍힘은 저장 완료의 변형으로 처리
  • 다음 단계 — 사이트맵·User Flow를 8화면 기준으로 갱신하고, 데이터 주석을 6주차 JSON 필드 명세로 이어감. watchedCategories ·체크리스트·도장 로직은 11~12주차 LocalStorage 구현 기준이 됨
